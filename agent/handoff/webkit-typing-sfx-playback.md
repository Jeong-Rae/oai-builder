# WebKit 타이핑 SFX 재생 문제와 Web Audio 전환

## 현상

최초 실행 튜토리얼의 타이핑 효과음이 Chromium 기반 삼성 인터넷에서는 글자마다 정상적으로 재생되지만, Safari와 WebKit 기반 브라우저에서는 각 단어의 마지막 글자에서만 한 번 재생되는 현상이 있었다.

화면의 글자 출력과 타이머 진행은 정상이었으며, `playSfx("typing")` 호출도 공백을 제외한 모든 글자에서 실행되고 있었다. 따라서 문제는 타이핑 상태나 문자열 분할이 아니라 실제 오디오 재생 계층에 있었다.

## 원인

기존 `src/game/sfx.ts`는 효과음 종류마다 `HTMLAudioElement`를 하나만 생성하고, 재생할 때마다 같은 요소를 다음과 같이 되감았다.

```ts
player.currentTime = 0;
void player.play().catch(() => {});
```

튜토리얼의 글자 출력 간격은 약 60~115ms이지만 타이핑 음원은 약 1.03초다. 따라서 한 단어를 출력하는 동안 같은 오디오 요소에 `currentTime` 탐색과 `play()` 요청이 연속해서 겹쳤다.

`HTMLMediaElement.currentTime` 변경은 즉시 별도의 재생 인스턴스를 만드는 동작이 아니라 비동기 미디어 탐색이다. Chromium에서는 음원의 시작 부분이 매번 들렸지만, WebKit에서는 짧은 간격의 탐색과 재생 요청이 실제 출력 전에 계속 대체되었다. 단어의 마지막 글자 뒤에는 공백 대기 시간이 있으므로 마지막 요청만 재생을 시작할 수 있었다.

## 적용한 수정

커밋 `9cd5fd9`에서 SFX 모듈을 Web Audio API 기반으로 변경했다.

- 각 음원 URL은 `fetch()`와 `decodeAudioData()`를 통해 `AudioBuffer`로 한 번만 디코딩한다.
- 재생할 때마다 일회용 `AudioBufferSourceNode`를 새로 생성한다.
- 같은 이름의 SFX가 다시 요청되면 직전 노드를 정지한 뒤 새 노드를 시작한다.
- 서로 다른 이름의 SFX는 독립적으로 재생할 수 있다.
- 음원 로딩 중 같은 SFX 요청이 여러 번 발생하면 요청 번호를 확인하여 마지막 요청만 재생한다.
- `AudioContext`가 `suspended` 상태이면 `playSfx()`가 `resume()`을 호출한다.
- 기존 공개 함수인 `preloadSfx()`와 `playSfx()`의 호출 방식은 유지했다.

이 구조에서는 재생 중인 미디어 요소의 재생 위치를 변경하지 않는다. Chromium과 WebKit 모두 새로운 소스 노드의 0초 지점에서 같은 방식으로 재생을 시작한다.

## 사용자 입력과 오디오 활성화

Safari는 사용자 입력이 발생하기 전에 생성된 `AudioContext`를 `suspended` 상태로 유지할 수 있다. 현재 `GameApp`은 버튼 클릭이 루트 요소로 전파될 때 `playSfx()`를 호출하므로, 최초 시작 버튼 클릭 안에서 `resume()` 요청도 실행된다.

타이핑은 시작 버튼 입력 이후에 진행되므로 정상적인 게임 진입 경로에서는 활성화된 컨텍스트를 사용한다. 향후 버튼 클릭을 거치지 않고 장면을 자동으로 시작하는 경로를 추가한다면, `pointerdown` 또는 `keydown` 사용자 입력에서 별도로 컨텍스트를 활성화해야 한다.

## 테스트와 검증

`tests/game/sfx.test.ts`의 테스트 대역을 `HTMLAudioElement`에서 `AudioContext`와 `AudioBufferSourceNode`로 변경했다. 테스트는 다음 동작을 확인한다.

1. 다섯 개의 SFX가 각각 한 번만 불러와지고 디코딩된다.
2. 정지된 오디오 컨텍스트가 최초 재생 시 활성화된다.
3. 같은 타이핑 SFX를 다시 요청하면 기존 소스가 정지된다.
4. 두 번째 요청은 별도의 소스 노드를 생성하고 출력 대상에 연결한 뒤 재생한다.

수정 시점에 다음 검증을 통과했다.

```bash
pnpm run typecheck
pnpm run test:run
pnpm run build:live
```

- 테스트 파일: 25개 통과
- 테스트: 179개 통과
- 게임 프로덕션 빌드 통과

## 남은 확인 사항

자동화 테스트에는 실제 WebKit 오디오 출력 장치가 없으므로 다음 수동 검증이 남아 있다.

1. Safari에서 최초 시작 버튼을 누른 뒤 첫 번째 튜토리얼 문장부터 글자마다 효과음이 들리는지 확인한다.
2. 긴 단어를 최저 입력 간격으로 출력해도 마지막 글자에서만 소리가 나는 현상이 재발하지 않는지 확인한다.
3. 타이핑 음원의 긴 잔향이 겹쳐서 음량이 커지지 않는지 확인한다.
4. 삼성 인터넷과 데스크톱 Chromium에서 기존 버튼, 이동, 클리어 효과음이 정상적으로 재생되는지 확인한다.
5. 탭을 백그라운드로 보냈다가 돌아온 뒤 오디오 컨텍스트가 다시 정지되는 Safari 환경이 있다면, 복귀 후 첫 사용자 입력에서 재생이 회복되는지 확인한다.

## 관련 파일과 작업 범위

- `src/game/sfx.ts`: Web Audio 기반 SFX 로딩과 재생 구현
- `src/game/scenes/tutorial/controller.ts`: 글자마다 타이핑 SFX를 요청하는 호출부
- `src/game/gameApp.ts`: SFX 사전 로드와 버튼 클릭 재생 호출부
- `tests/game/sfx.test.ts`: Web Audio 재생 교체 동작 테스트

작성 시점에 작업 트리에는 별도의 BGM 구현과 `src/game/gameApp.ts` 변경 사항이 남아 있었다. 해당 변경은 SFX 수정 커밋 `9cd5fd9`에 포함되지 않았으므로, 후속 작업에서도 두 작업의 범위를 구분해야 한다.
