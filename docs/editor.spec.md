# Map Editor 요구사항

이 문서는 Map Editor의 맵 편집, 라이브 테스트, `.map` 파일 내보내기 및 불러오기 요구사항을 정의한다. 모든 요구사항은 EARS(Easy Approach to Requirements Syntax) 형식으로 작성한다.

## 용어 및 좌표

- `맵 초안`은 에디터에서 저장 및 테스트 대상으로 편집 중인 맵 설정을 의미한다.
- `테스트 상태`는 맵 초안으로 게임을 실행하는 동안 변경되는 일시적인 게임 상태를 의미한다.
- `N`은 맵의 열 수, `M`은 맵의 행 수를 의미한다.
- 셀 좌표의 원점은 좌상단 `(0, 0)`이며, `x`는 오른쪽으로, `y`는 아래쪽으로 증가한다.
- 필드 종류는 `blank`, `floor`, `wall`, `plate`, `exit` 중 하나를 의미한다.
- 오브젝트 종류는 `player`, `normal`, `handoff`, `swapper` 중 하나를 의미한다.
- `exit`는 골을 나타내는 필드이며 엔티티가 아니다.
- `본 게임 앱`은 완성된 맵을 플레이하는 배포 단위를 의미한다.
- `에디터 앱`은 맵을 편집하고 라이브 테스트하는 배포 단위를 의미한다.

## 에디터 진입 및 기본 상태

- ME-RQ-001: Map Editor가 열리면, 에디터는 맵 크기 설정 영역, 편집 도구 영역, 셀 그리드, 검증 결과 영역, 라이브 테스트 실행 기능, 내보내기 기능 및 불러오기 기능을 제공해야 한다.
- ME-RQ-002: 새 맵 생성이 요청되면, 에디터는 지정된 `N`과 `M`으로 맵 초안을 생성해야 한다.
- ME-RQ-003: 크기를 지정하지 않고 새 맵 생성이 요청되면, 에디터는 기본 크기 9×9의 맵 초안을 생성해야 한다.
- ME-RQ-004: 새 맵이 생성되면, 에디터는 모든 셀의 필드를 `floor`로 설정해야 한다.
- ME-RQ-005: 새 맵이 생성되면, 에디터는 플레이어, 골 및 다른 오브젝트가 배치되지 않은 상태로 맵 초안을 생성해야 한다.
- ME-RQ-006: 맵 초안이 변경되면, 에디터는 저장되지 않은 변경 사항이 있음을 표시해야 한다.

## 맵 크기

- ME-RQ-007: 에디터는 `N`과 `M`을 각각 1 이상의 정수로 입력받아야 한다.
- ME-RQ-008: 맵 크기 변경이 적용되면, 에디터는 셀 그리드를 `N`열 × `M`행으로 갱신해야 한다.
- ME-RQ-009: 맵 크기가 확장되면, 에디터는 기존 범위와 같은 좌표의 셀 설정을 유지해야 한다.
- ME-RQ-010: 맵 크기가 확장되면, 에디터는 새로 생긴 셀의 필드를 `floor`로 설정해야 한다.
- ME-RQ-011: 맵 크기 축소로 설정된 셀, 오브젝트, 플레이어 또는 골이 제거될 수 있으면, 에디터는 크기 변경을 적용하기 전에 제거될 항목이 있음을 사용자에게 확인받아야 한다.
- ME-RQ-012: 사용자가 내용 제거를 동반하는 맵 크기 축소를 승인하면, 에디터는 새 범위 밖의 셀과 해당 셀에 배치된 항목을 맵 초안에서 제거해야 한다.
- ME-RQ-013: 사용자가 내용 제거를 동반하는 맵 크기 축소를 취소하면, 에디터는 기존 맵 크기와 맵 초안을 유지해야 한다.
- ME-RQ-014: `N` 또는 `M`이 1 이상의 정수가 아니면, 에디터는 크기 변경을 적용하지 않고 해당 입력의 오류를 표시해야 한다.

## 셀 및 필드 편집

- ME-RQ-015: 에디터는 맵 초안의 모든 좌표에 정확히 하나의 셀을 표시해야 한다.
- ME-RQ-016: 에디터는 각 셀의 현재 필드 종류를 시각적으로 구분해 표시해야 한다.
- ME-RQ-017: 사용자가 필드 도구를 선택하고 셀을 지정하면, 에디터는 해당 셀의 필드를 선택한 필드 종류로 변경해야 한다.
- ME-RQ-018: 사용자가 여러 셀을 연속해서 지정하면, 에디터는 선택한 필드 도구를 지정된 각 셀에 적용해야 한다.
- ME-RQ-019: 오브젝트가 배치된 셀의 필드가 `wall`로 변경되면, 에디터는 해당 오브젝트를 제거하기 전에 사용자에게 확인받아야 한다.
- ME-RQ-020: 사용자가 오브젝트 제거를 승인하면, 에디터는 해당 셀의 오브젝트를 제거하고 필드를 `wall`로 변경해야 한다.
- ME-RQ-021: 사용자가 오브젝트 제거를 취소하면, 에디터는 해당 셀의 필드와 오브젝트를 변경하지 않아야 한다.
- ME-RQ-022: 골이 있는 셀에 `exit` 이외의 필드가 적용되면, 에디터는 해당 셀의 골을 제거하고 선택한 필드를 적용해야 한다.
- ME-RQ-023: 사용자가 골 도구를 선택하고 셀을 지정하면, 에디터는 해당 셀의 필드를 `exit`로 설정해야 한다.
- ME-RQ-024: `exit` 필드가 이미 존재하는 상태에서 사용자가 다른 셀에 골을 배치하면, 에디터는 기존 `exit` 필드를 `floor`로 변경하고 지정된 셀을 `exit`로 설정해야 한다.

## 오브젝트 편집

- ME-RQ-025: 에디터는 플레이어, 일반 오브젝트, 핸드오프 앵커 및 스와퍼 배치 도구를 제공해야 한다.
- ME-RQ-026: 사용자가 오브젝트 도구를 선택하고 오브젝트를 배치할 수 있는 셀을 지정하면, 에디터는 해당 좌표에 선택한 종류의 오브젝트를 배치해야 한다.
- ME-RQ-027: 에디터는 하나의 셀에 최대 하나의 오브젝트만 배치해야 한다.
- ME-RQ-028: 사용자가 오브젝트가 있는 셀에 다른 오브젝트를 배치하면, 에디터는 기존 오브젝트를 선택한 오브젝트로 교체해야 한다.
- ME-RQ-029: 사용자가 `wall` 셀에 오브젝트를 배치하려 하면, 에디터는 배치를 적용하지 않고 해당 셀에 오브젝트를 배치할 수 없음을 표시해야 한다.
- ME-RQ-030: 에디터는 `floor`, `plate` 또는 `exit` 셀에 오브젝트를 배치하도록 허용해야 한다.
- ME-RQ-031: 플레이어가 이미 존재하는 상태에서 사용자가 다른 셀에 플레이어를 배치하면, 에디터는 기존 플레이어를 제거하고 지정된 셀로 플레이어를 이동해야 한다.
- ME-RQ-032: 일반 오브젝트, 핸드오프 앵커 또는 스와퍼가 배치되면, 에디터는 해당 오브젝트에 맵 초안 내에서 고유한 식별자를 부여해야 한다.
- ME-RQ-033: 사용자가 지우기 도구로 오브젝트가 있는 셀을 지정하면, 에디터는 필드를 유지하고 해당 오브젝트만 제거해야 한다.
- ME-RQ-034: 사용자가 지우기 도구로 오브젝트가 없는 `exit` 셀을 지정하면, 에디터는 해당 셀의 필드를 `floor`로 변경해야 한다.
- ME-RQ-035: 맵 초안으로 게임의 최초 상태가 생성되면, 게임 시스템은 `↑`, `↓`, `←`, `→` 컨트롤을 모두 플레이어에게 할당해야 한다.
- ME-RQ-036: 맵 초안으로 게임의 최초 상태가 생성되면, 게임 시스템은 플레이어 이외의 오브젝트를 빈 컨트롤 집합으로 생성해야 한다.

## 편집 표시 및 선택

- ME-RQ-037: 사용자가 셀을 가리키거나 선택하면, 에디터는 대상 셀을 다른 셀과 구분해 표시해야 한다.
- ME-RQ-038: 사용자가 셀을 선택하면, 에디터는 해당 셀의 좌표, 필드 종류 및 배치된 오브젝트 종류를 표시해야 한다.
- ME-RQ-039: 편집 도구가 선택되면, 에디터는 현재 선택된 도구를 표시해야 한다.
- ME-RQ-040: 필드와 오브젝트가 같은 셀에 존재하면, 에디터는 두 설정을 모두 식별할 수 있도록 표시해야 한다.
- ME-RQ-041: 맵 초안이 변경되면, 에디터는 변경 결과를 별도의 페이지 새로고침 없이 셀 그리드에 반영해야 한다.

## 맵 유효성 검증

- ME-RQ-042: 맵 초안이 변경되면, 에디터는 현재 맵의 유효성을 다시 검사해야 한다.
- ME-RQ-043: 맵에 플레이어가 정확히 하나 존재하지 않으면, 에디터는 맵을 유효하지 않은 상태로 판정하고 플레이어 관련 오류를 표시해야 한다.
- ME-RQ-044: 맵에 `exit` 필드가 정확히 하나 존재하지 않으면, 에디터는 맵을 유효하지 않은 상태로 판정하고 골 관련 오류를 표시해야 한다.
- ME-RQ-045: 오브젝트의 좌표가 맵 범위를 벗어나면, 에디터는 맵을 유효하지 않은 상태로 판정하고 해당 오브젝트의 오류를 표시해야 한다.
- ME-RQ-046: 하나의 좌표에 둘 이상의 오브젝트가 정의되면, 에디터는 맵을 유효하지 않은 상태로 판정하고 중복 점유 오류를 표시해야 한다.
- ME-RQ-047: 오브젝트가 `wall` 셀에 정의되면, 에디터는 맵을 유효하지 않은 상태로 판정하고 해당 좌표의 오류를 표시해야 한다.
- ME-RQ-048: 맵 데이터에 지원하지 않는 필드 또는 오브젝트 종류가 포함되면, 에디터는 맵을 유효하지 않은 상태로 판정하고 지원하지 않는 종류를 표시해야 한다.
- ME-RQ-049: 맵 초안이 유효하지 않은 동안, 에디터는 편집 그리드의 방향키 테스트와 내보내기를 허용하지 않아야 한다.
- ME-RQ-050: 맵 초안의 모든 오류가 해소되면, 에디터는 편집 그리드의 방향키 테스트와 내보내기를 허용해야 한다.

## 라이브 테스트

- ME-RQ-051: 맵 초안이 유효해지면, 에디터는 현재 맵 초안으로 테스트 상태를 생성하고 편집 그리드에서 즉시 테스트할 수 있는 상태로 전환해야 한다.
- ME-RQ-052: 테스트 상태가 생성되면, 게임 시스템은 맵 초안의 크기, 필드, 오브젝트, 플레이어 위치 및 골 위치를 동일한 편집 그리드에 반영해야 한다.
- ME-RQ-053: 편집 그리드에서 방향키가 입력되면, 게임 시스템은 일반 게임과 동일한 이동, 컨트롤 전달, 플레이트, 핸드오프, 스와퍼 및 골 규칙을 적용해야 한다.
- ME-RQ-054: 방향키 테스트 중 테스트 상태가 변경되면, 에디터는 변경된 필드 상태, 오브젝트 위치, 컨트롤 소유권 및 게임 완료 상태를 동일한 편집 그리드에 즉시 렌더링해야 한다.
- ME-RQ-055: 라이브 테스트 중 게임 상태가 변경되면, 에디터는 맵 초안을 변경하지 않아야 한다.
- ME-RQ-056: 사용자가 배치 상태 복원을 요청하면, 에디터는 기존 테스트 상태를 폐기하고 현재 맵 초안으로 테스트 상태를 다시 생성해야 한다.
- ME-RQ-057: 테스트 중 맵 편집이 발생하면, 에디터는 해당 편집을 맵 초안에 적용하고 변경된 맵 초안으로 테스트 상태를 다시 생성해야 한다.
- ME-RQ-058: 라이브 테스트가 완료 상태에 도달하면, 에디터는 동일한 편집 그리드에 완료 상태와 배치 상태 복원 기능을 표시해야 한다.

## `.map` 파일 형식

- ME-RQ-059: 에디터는 `.map` 파일을 UTF-8로 인코딩된 JSON 문서로 관리해야 한다.
- ME-RQ-060: `.map` 문서는 파일 형식 버전, 열 수, 행 수, 셀별 필드 정보 및 오브젝트 정보를 포함해야 한다.
- ME-RQ-061: `.map` 문서의 필드 정보는 맵의 모든 좌표에 대한 필드 종류를 손실 없이 표현해야 한다.
- ME-RQ-062: `.map` 문서의 오브젝트 정보는 각 오브젝트의 종류, 고유 식별자 및 좌표를 포함해야 한다.
- ME-RQ-063: `.map` 문서는 플레이어를 오브젝트 정보에 포함하고 골을 `exit` 필드로 포함해야 한다.
- ME-RQ-064: `.map` 문서는 라이브 테스트 중 변경된 위치, 컨트롤 소유권, 플레이트 활성 상태, 골 개방 상태 또는 게임 완료 상태를 포함하지 않아야 한다.
- ME-RQ-065: 동일한 맵 초안을 내보낸 뒤 다시 불러오면, 에디터는 내보내기 전과 동일한 크기, 필드, 오브젝트 종류, 오브젝트 식별자 및 좌표를 복원해야 한다.

## 내보내기

- ME-RQ-066: 유효한 맵에서 내보내기가 요청되면, 에디터는 현재 맵 초안을 `.map` 파일로 생성해야 한다.
- ME-RQ-067: 내보낼 파일 이름에 `.map` 확장자가 없으면, 에디터는 파일 이름 끝에 `.map`을 추가해야 한다.
- ME-RQ-068: 내보내기가 완료되면, 에디터는 현재 맵 초안을 저장된 상태로 표시해야 한다.
- ME-RQ-069: 라이브 테스트 중 내보내기가 요청되면, 에디터는 테스트 상태가 아닌 맵 초안을 내보내야 한다.

## 불러오기

- ME-RQ-070: 사용자가 `.map` 파일을 선택하면, 에디터는 해당 파일을 읽고 JSON 및 파일 형식 버전을 검사해야 한다.
- ME-RQ-071: 선택한 파일의 확장자가 `.map`이 아니면, 에디터는 기존 맵 초안을 유지하고 지원하지 않는 파일 형식임을 표시해야 한다.
- ME-RQ-072: 선택한 `.map` 파일을 JSON으로 해석할 수 없으면, 에디터는 기존 맵 초안을 유지하고 파일을 해석할 수 없음을 표시해야 한다.
- ME-RQ-073: `.map` 파일의 버전을 지원하지 않으면, 에디터는 기존 맵 초안을 유지하고 지원하지 않는 버전을 표시해야 한다.
- ME-RQ-074: `.map` 파일에 필수 데이터가 없거나 데이터 형식이 올바르지 않으면, 에디터는 기존 맵 초안을 유지하고 검증 오류를 표시해야 한다.
- ME-RQ-075: `.map` 파일이 맵 유효성 규칙을 위반하면, 에디터는 기존 맵 초안을 유지하고 위반한 규칙과 관련 좌표를 표시해야 한다.
- ME-RQ-076: 저장되지 않은 변경 사항이 있는 동안 유효한 `.map` 파일이 선택되면, 에디터는 현재 맵 초안을 교체하기 전에 사용자에게 확인받아야 한다.
- ME-RQ-077: 사용자가 맵 초안 교체를 승인하면, 에디터는 `.map` 파일의 데이터로 맵 초안을 교체하고 해당 맵을 셀 그리드에 표시해야 한다.
- ME-RQ-078: 사용자가 맵 초안 교체를 취소하면, 에디터는 기존 맵 초안을 유지해야 한다.
- ME-RQ-079: `.map` 파일 불러오기가 완료되면, 에디터는 기존 테스트 상태를 폐기하고 불러온 맵을 편집 가능한 상태로 표시해야 한다.

- ME-RQ-082: 자동화된 테스트가 실행되면, 테스트는 맵 크기 변경, 셀 편집, 단일 플레이어와 골 제약, 맵 검증, 테스트 상태 격리 및 `.map` 왕복 변환을 검증해야 한다.
- ME-RQ-083: 자동화된 테스트가 실행되면, 테스트는 잘못된 확장자, 잘못된 JSON, 지원하지 않는 버전 및 유효하지 않은 맵 데이터가 기존 맵 초안을 변경하지 않는지 검증해야 한다.
- ME-RQ-084: 프로덕션 빌드가 생성되면, 검증 절차는 Map Editor의 편집, 라이브 테스트, 파일 내보내기 및 파일 불러오기를 수동 브라우저 점검으로 확인해야 한다.

- ME-RQ-085: 본 게임 앱이 실행되면, 시스템은 본 게임 전용 진입점으로 게임을 시작해야 한다.
- ME-RQ-086: 에디터 앱이 실행되면, 시스템은 에디터 전용 진입점으로 Map Editor를 시작해야 한다.
- ME-RQ-087: 본 게임 앱이 빌드되면, 빌드 시스템은 본 게임만 독립적으로 배포할 수 있는 `dist/game` 산출물을 생성해야 한다.
- ME-RQ-088: 에디터 앱이 빌드되면, 빌드 시스템은 에디터만 독립적으로 배포할 수 있는 `dist/editor` 산출물을 생성해야 한다.
- ME-RQ-089: 전체 프로덕션 빌드가 요청되면, 빌드 시스템은 본 게임과 에디터의 독립 배포 산출물을 모두 생성해야 한다.
- ME-RQ-090: 본 게임 개발 서버가 요청되면, 개발 시스템은 에디터 앱을 시작하지 않고 본 게임 앱을 제공해야 한다.
- ME-RQ-091: 에디터 개발 서버가 요청되면, 개발 시스템은 본 게임 앱을 최초 화면으로 시작하지 않고 에디터 앱을 제공해야 한다.
- ME-RQ-092: 본 게임 앱이 빌드되면, 빌드 시스템은 에디터 화면과 에디터 상태 관리 코드를 본 게임 진입 번들에 포함하지 않아야 한다.
- ME-RQ-093: 에디터 앱이 맵을 테스트하면, 에디터는 본 게임과 동일한 게임 도메인 규칙 및 맵 문서 형식을 사용해야 한다.
- ME-RQ-094: 본 게임 코드가 컴파일되면, 본 게임 앱은 에디터 전용 모듈을 참조하지 않아야 한다.
- ME-RQ-095: 본 게임과 에디터가 배포되면, 배포 시스템은 각 앱을 서로 다른 서브도메인의 루트 경로에서 제공할 수 있어야 한다.
- ME-RQ-096: 한 앱의 새 버전만 배포되면, 배포 시스템은 다른 앱의 산출물을 다시 배포하지 않고 해당 앱의 산출물만 교체할 수 있어야 한다.
- ME-RQ-097: `.map` 버전 1 문서가 생성되면, 에디터는 루트 객체에 `version`, `columns`, `rows`, `tiles`, `objects` 키를 기록해야 한다.
- ME-RQ-098: `.map` 버전 1 문서가 생성되면, 에디터는 `tiles`를 `M`개의 행과 각 행의 `N`개 필드 종류로 구성된 행 우선 배열로 기록해야 한다.
- ME-RQ-099: `.map` 버전 1 문서가 생성되면, 에디터는 각 오브젝트를 `id`, `kind`, `position`으로 구성하고 `position`을 `x`, `y` 좌표로 기록해야 한다.
- ME-RQ-100: `.map` 버전 1 문서가 불러와지면, 에디터는 `version` 값 `1`을 지원 버전으로 처리해야 한다.

- ME-RQ-103: 방향키 테스트로 오브젝트 위치 또는 필드 상태가 변경되면, 에디터는 편집 시 사용한 것과 동일한 이미지 에셋으로 변경 상태를 렌더링해야 한다.
- ME-RQ-104: 필드 또는 오브젝트가 선택되면, 에디터는 이미지 에셋을 가리지 않는 테두리 또는 오버레이로 선택 상태를 표시해야 한다.

## Blank 필드

- ME-RQ-105: 사용자가 `blank` 필드 도구를 선택하고 셀을 지정하면, 에디터는 해당 셀의 필드를 `blank`로 설정해야 한다.
- ME-RQ-106: `blank` 셀이 렌더링되면, 에디터와 본 게임은 해당 셀에 바닥 또는 다른 필드 이미지 에셋을 렌더링하지 않아야 한다.
- ME-RQ-107: 사용자가 `blank` 셀에 오브젝트를 배치하려 하면, 에디터는 배치를 적용하지 않고 해당 셀이 맵 외부 영역임을 표시해야 한다.
- ME-RQ-108: 오브젝트가 배치된 셀의 필드가 `blank`로 변경되면, 에디터는 해당 오브젝트를 제거하기 전에 사용자에게 확인받아야 한다.
- ME-RQ-109: 행동 주체가 `blank` 셀을 향해 컨트롤을 입력하면, 게임 시스템은 위치 또는 컨트롤 소유권을 변경하지 않고 `out-of-bounds` 거절 사유를 반환해야 한다.
- ME-RQ-110: `.map` 문서가 생성되면, 에디터는 `blank`를 다른 필드 종류와 동일하게 셀별 필드 정보에 기록해야 한다.

## 웜홀과 게이트 필드

- ME-RQ-111: 에디터가 필드 도구를 표시하면, 에디터는 웜홀과 게이트 필드 도구를 제공해야 한다.
- ME-RQ-112: 사용자가 웜홀 또는 게이트 필드를 셀에 배치하면, 에디터는 해당 셀을 이동하지 않는 고정형 필드로 저장해야 한다.
- ME-RQ-113: 웜홀이 두 개 배치되면, 에디터는 두 웜홀을 하나의 고정된 `1:1` 연결로 표시해야 한다.
- ME-RQ-114: 웜홀 필드가 한 개이면, 에디터는 맵을 유효하지 않은 상태로 판정하고 짝이 필요하다는 오류를 표시해야 한다.
- ME-RQ-115: 웜홀 필드가 두 개이면, 에디터는 두 위치의 연결을 라이브 테스트와 `.map` 왕복 변환에서 동일하게 유지해야 한다.
- ME-RQ-116: 라이브 테스트 중 일반 오브젝트가 플레이트를 하나 이상 점유하면, 에디터는 모든 게이트를 열린 상태로 즉시 표시해야 한다.
- ME-RQ-117: 라이브 테스트 중 마지막 일반 오브젝트가 플레이트에서 이탈하면, 에디터는 모든 게이트를 닫힌 상태로 즉시 표시해야 한다.
- ME-RQ-118: 웜홀 또는 게이트 셀이 렌더링되면, 에디터는 해당 필드 종류와 웜홀 연결 또는 게이트 상태를 구분할 수 있는 에셋 또는 오버레이를 표시해야 한다.
- ME-RQ-119: 웜홀 필드가 이미 두 개 존재하는 동안 사용자가 세 번째 웜홀을 배치하려 하면, 에디터는 배치를 적용하지 않고 웜홀은 두 개로 제한됨을 표시해야 한다.

## 로컬 에셋 시험

- ME-RQ-120: 사용자가 좌측의 필드 또는 오브젝트 도구를 선택하면, 에디터는 해당 도구가 사용하는 에셋을 우측 이미지 수정 영역의 적용 대상으로 자동 선택해야 한다.
- ME-RQ-121: 사용자가 이미지 에셋이 없는 도구를 선택하면, 에디터는 우측 이미지 수정 영역에서 이미지 적용을 비활성화하고 이유를 표시해야 한다.
- ME-RQ-122: 사용자가 이미지 파일을 선택하면, 에디터는 해당 파일을 서버에 전송하거나 저장하지 않고 현재 브라우저에서만 자동 선택된 에셋의 대체 이미지로 적용해야 한다.
- ME-RQ-123: 로컬 에셋이 적용되면, 에디터는 도구 미리보기, 편집 그리드 및 라이브 테스트의 해당 이미지에 즉시 같은 대체 이미지를 렌더링해야 한다.
- ME-RQ-124: 선택한 파일을 이미지로 읽을 수 없으면, 에디터는 기존 에셋을 유지하고 파일을 읽을 수 없음을 표시해야 한다.
- ME-RQ-125: 사용자가 기본 에셋 복원을 요청하면, 에디터는 모든 로컬 에셋 대체 이미지를 제거하고 기본 런타임 에셋을 즉시 렌더링해야 한다.
- ME-RQ-126: 로컬 에셋 대체 이미지는 맵 초안, `.map` 파일 또는 저장되지 않은 맵 변경 상태에 포함하지 않아야 한다.
- ME-RQ-127: Map Editor가 종료되거나 브라우저가 새로고침되면, 에디터는 로컬 에셋 대체 이미지의 브라우저 메모리 참조를 해제해야 한다.

## 일괄 초기화

- ME-RQ-128: 사용자가 필드 지우기를 승인하면, 에디터는 현재 맵 크기를 유지하고 모든 필드를 `floor`로 변경해야 한다.
- ME-RQ-129: 사용자가 오브젝트 지우기를 승인하면, 에디터는 현재 필드를 유지하고 플레이어를 포함한 모든 오브젝트를 제거해야 한다.
- ME-RQ-130: 사용자가 맵 초기화를 승인하면, 에디터는 현재 맵 크기를 유지하고 모든 필드를 `floor`로 변경하며 모든 오브젝트를 제거해야 한다.
- ME-RQ-131: 사용자가 필드 지우기, 오브젝트 지우기 또는 맵 초기화를 취소하면, 에디터는 현재 맵 초안을 변경하지 않아야 한다.
